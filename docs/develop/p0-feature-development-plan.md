# Markdown Reader P0 功能开发计划（逐 Feature 验收）

## 1. 目标与协作方式

本计划用于把 `TODO.md` 中 `P0` 项（`mermaid渲染` 到 `正文可折叠`）拆成可逐个交付、逐个验收的功能包。

状态标记说明：

- `已完成`：已开发并由你验收通过
- `进行中`：正在开发
- `待开发`：尚未进入开发

协作节奏：

1. 我一次只实现 1 个 Feature（或该 Feature 的 1 个明确子阶段）。
2. 你验收这一项的交互和效果。
3. 你确认通过后，再进入下一项。
4. 若验收发现偏差，我先修正当前 Feature，不并行推进后续项。

## 2. P0 需求细化与 Feature 拆分

> 说明：F5、F6 复杂度明显高于前 4 项，建议分阶段落地，先保证最小可用再增强交互。

1. F4 一级标题来源修正（已完成）
2. F3 目录滚动边界隔离（已完成）

这样排的原因：

- Mermaid 基础渲染（F1）已具备，当前只聚焦放大按钮进入全屏后的交互增强（F2）。
- 编辑和拖动会改动面更大，放到后半段更稳。

## 4. 每个 Feature 的实现定义与验收标准

## F4 一级标题来源修正（优先级最高）

### 目标

目录与正文结构中，一级标题应来自 Markdown 中的 `# ` 标题，而不是“文件名注入的伪一级标题”。

### 实现范围

- 调整标题提取/编号逻辑：仅对真实 Markdown 标题建树。
- 若文档不存在 `#` 标题：
  - 不自动创建“文件名一级标题”。
  - 目录可为空或从次级标题开始（以代码实现可维护性为准）。

### 验收标准

- 含 `# 标题` 的文件：目录第一级与正文对应一致。
- 不含 `#` 但含 `##` 的文件：不出现文件名伪标题。
- 现有 cite、anchor 跳转不回归。

### 测试点

- `docs/fixtures` 下准备 3 类样例：有 H1、无 H1、有多级标题。

## F3 目录滚动边界隔离

### 目标

当鼠标位于目录区域滚动且目录已到顶部/底部时，不把滚动事件继续传递到正文容器。

### 实现范围

- 在目录容器处理 `wheel` 事件。
- 到达边界时拦截默认滚动传递（防止“串滚”）。
- 正文区域维持自身滚动，不受目录滚动行为污染。

### 验收标准

- 目录滚动到顶后继续上滚：正文不动。
- 目录滚动到底后继续下滚：正文不动。
- 鼠标位于正文区域时滚动仍正常。

### 测试点

- 鼠标悬停位置切换（目录/正文）时反复滚动，确认无抖动、无串滚。

## F2 Mermaid 全屏查看交互（由右上角放大按钮触发）

### 目标

点击 Mermaid 卡片右上角放大按钮后进入“全屏查看态”，在全屏内支持滚轮缩放、左键拖动画布。

### 实现范围

- 点击 Mermaid 右上角放大按钮进入全屏 overlay/modal。
- 滚轮缩放（有最小/最大缩放限制，避免无限缩放）。
- 左键按下拖动视图位置（释放停止）。
- 提供退出方式（Esc、关闭按钮、点击遮罩三选二以上）。

### 验收标准

- 从按钮进入全屏路径稳定可用（不是点击图任意区域触发）。
- 全屏内能流畅放大缩小并拖动。
- 切换到下一张 Mermaid 时状态可重置（不会继承上次异常偏移）。
- 不影响正文正常滚动与点击。

### 测试点

- 连续打开多个图、快速缩放、快速拖动，检查事件泄漏与卡顿。

## F5 文档编辑 + Markdown 原生内链跳转（建议分 2 个子阶段）

### 子阶段 F5-1：基础编辑能力（最小可用）

状态：`已完成`

#### 目标

在阅读器中提供“可编辑”模式，编辑体验接近 Obsidian/飞书的基础可用水平。

#### 范围建议（MVP）

- 编辑/预览双模式切换（先不做复杂所见即所得块编辑）。
- 文本编辑后可保存回当前 `.md` 文档。
- 保留当前阅读能力（目录、cite、代码块渲染）。

#### 验收标准

- 可进入编辑模式修改文本并保存。
- 保存后刷新预览内容一致。
- 不破坏现有打开/重开流程。

### 子阶段 F5-2：Markdown 原生内链语法

状态：`进行中`

#### 目标

在文档中使用 Markdown 原生内链（如 `[跳转到安装章节](#安装)`）实现标题位置跳转，并支持返回原文位置（来源位置）。

#### 范围建议

- 语法解析：支持 Markdown 原生文档内锚点链接语法（`[文本](#锚点)`）。
- 锚点规则与标题生成规则保持一致（slug 规则统一，避免“能渲染但跳不过去”）。
- 渲染样式：保持标准链接样式，可在交互态（如激活态）增加轻量增强。
- 点击跳转到目标标题；支持“返回来源位置”。
- 目标不存在时给出降级提示（不可点击或提示失效引用）。

#### 验收标准

- 正确跳转、正确返回。
- 多个内链连续点击不串位。
- 与 `[cite: n]` 逻辑互不干扰。

## F6 模块拖动 + 折叠联动（建议分 2 个子阶段）

### 子阶段 F6-1：正文折叠/目录联动

#### 目标

支持正文按标题层级折叠；折叠正文节点时，目录对应节点同步折叠。反向不联动：折叠目录不应折叠正文。

#### 范围建议

- 正文块折叠状态管理（基于标题树）。
- 正文折叠 -> 目录同步折叠。
- 目录折叠仅影响目录显示，不改正文状态。

#### 验收标准

- 正文折叠行为与目录联动规则符合需求。
- 刷新后可按策略恢复状态（可选：先不持久化，后续增强）。

### 子阶段 F6-2：模块拖动重排

#### 目标

支持以“块”为单位拖动重排（段落、标题及其子级、图片、mermaid 图、代码块）。

#### 范围建议（按风险分层）

- 先支持“标题块（含子树）拖动”与“普通段落块拖动”。
- 再扩展到图片、代码块、Mermaid 图。
- 明确数据模型：拖动后更新 Markdown 文本结构，而非仅视觉顺序变更。

#### 验收标准

- 拖动后文档结构和目录一致更新。
- 保存后重新打开，顺序保持一致。
- 不出现块内容丢失、跨层级错位。

## 5. 逐 Feature 交付模板（每次开发都按这个走）

每个 Feature 我会按以下结构交付：

1. 实现范围（本次只做哪些，不做哪些）
2. 影响文件清单
3. 手工验证步骤（你可直接操作验证）
4. 已知限制/待下一步增强

你确认后，我再继续下一个 Feature。

## 6. 风险与提前约束

- F5/F6 涉及“编辑器能力 + 文档结构改写”，风险最高。
- 拖动功能如果直接覆盖所有块类型，容易造成结构错乱；建议分层上线。
- Markdown 原生内链依赖稳定锚点规则；需先确保 F4 后标题结构与 anchor 生成策略固定。
- Mermaid 放大交互要注意事件释放，避免出现关闭后页面仍被拦截滚动。
