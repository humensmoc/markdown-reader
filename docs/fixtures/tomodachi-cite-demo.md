## 正文

### 一、研究范围与方法

**研究问题**：收集 Island Lingo 之后，游戏按 person / thing / activity / something else 等分类，Mii 在「小剧场」里如何具体使用这些词条？

**「小剧场」在本项目语境中的含义**：并非英文 Wiki 的固定专名，而是设计笔记中对 **Mii 之间自主或半自主互动场景** 的统称，主要包括：

| 场景类型 | 触发方式 | 与 Island Lingo 的关系 |
|---------|---------|----------------------|
| 拖动互动 | 将 Mii 拖到另一 Mii 身边 | 强制发起对话或 cutscene，系统从词库抽词填入句型 [cite: 1] |
| Hangout cutscene | Mii 相处时头顶黄条纹 | 可观看的相处小场景，揭示关系动态 [cite: 2] |
| 橙色交友气泡 | 同意 Mii 交友/同住/感谢等请求 | 玩家指定 lingo 作为当场 cutscene 话题 [cite: 3] |
| Tomoria 餐厅事件 | Robot Rally、Fan Meetup 等 | 直接插入玩家录入的 Island Lingo [cite: 4] |

**信息截止**：2026 年 4–6 月公开资料（游戏 2026-04-16 发售）。

**置信度说明**：Primary（任天堂 UK [cite: 9]）、Secondary（Game8、Living The Grid、Fandom Wiki）、Tertiary（Kotaku 转述玩家视频 [cite: 14]、Laura Michet 博客 [cite: 11]、社区攻略）分层使用；无 primary 逐类台词库时，不编造未出现的完整句型清单。

### 二、Island Lingo 录入与分类

#### 2.1 录入入口

Miis 在以下情境向玩家索要 Island Lingo：

- 黄色「Chat」气泡：「Do you have time for a quick chat?」→ 录入新 lingo [cite: 5]
- 橙色交友气泡：想交友、介绍两人、同住、表达感谢等 → 指定「聊什么」 [cite: 5]
- 升级 / 现实世界提问等（Speech Bubble 奖杯进度） [cite: 6]

录入流程：输入词或短语 → 设置发音 → **选择用途分类** → 写入 Island Dictionary。

#### 2.2 可确认的分类体系

| 分类 | 英文界面表述 | 来源 |
|------|-------------|------|
| 人物 | person | [cite: 7] |
| 事物 | thing | [cite: 7] |
| 活动 | activity | [cite: 7] |
| 其他 | something else | [cite: 7] |
| （变体）地点 | place | [cite: 8]（与 person/thing/activity 四分类并存于不同来源，以四分类为主流表述） |

**分类的功能性含义**（非纯标签）：

- NeonLightsMedia：分类决定 Mii 如何与世界互动 [cite: 8]
- 任天堂 UK：录入后可按 usage 调整语法属性，例如 **a / an** [cite: 9]
- Living The Grid：保存后**不能改原文**，仅能改发音与冠词 [cite: 10]

#### 2.3 词库的全岛共享规则

- 词条**不绑定**最初提问的 Mii，进入 Island Dictionary 后**全岛通用** [cite: 8]
- Miis 以**随机轮播**方式使用词条；词库越大，对话越不可预测 [cite: 10]
- 删除词条后居民停止谈论 [cite: 9]

### 三、小剧场中的总机制：storylet + 槽位填充

公开设计向描述（Laura Michet [cite: 11]）将互动理解为 **预制 storylet + 玩家文本槽位**：

- 游戏在 cutscene 触发时「选角」并填入模板 [cite: 11]
- 玩家录入的 lingo 构成「island lingo」词库，Miis 在 cutscene 与日常中复用 [cite: 11]
- 同一概念可在**相关 Mii 不在场**的 cutscene 中出现 [cite: 11]（以 *Democratic Socialism* 为例）

**与玩家操作相关的规则**：

| 规则 | 说明 | 依据 |
|------|------|------|
| 新建优于复用 | 交友时输入**新** lingo 比复用旧词成功率更高 | [cite: 12] |
| 话题匹配关系 | 同住 cutscene 成功与否与话题是否对口相关 | [cite: 3] |
| 已有 lingo 可选 | 橙色气泡中也可从已有词库选话题 | [cite: 10] |
| 玩家 lingo 高亮 | 交友对话中玩家自创词常以**橙色**标出 | [cite: 13] |
| Chat 类语境绑定 | 通过 Chat 问题录入的 lingo 可能绑定特定复现场景 | [cite: 5] |

### 四、按分类：小剧场中的具体用法

以下每类仅列**可溯源**的句型、事件或行为模式；未在来源中出现的句式不作推断。

#### 4.0 本次新增：真实/占位符模板清单

这一节专门解决「统计太泛」的问题：把已看到的中文实录、公开页面的事件描述、以及可替换槽位拆开列。表中「证据类型」分三档：

| 证据类型 | 含义 |
|----------|------|
| 逐句实录 | 玩家实际看到或公开文章逐字转录的句子 |
| 事件描述 | Wiki/攻略页明确说该事件会使用 Lingo/Food/Treasure 等槽位，但未给完整逐句台词 |
| 归纳模板 | 从多条实录中扣掉可替换内容后的模板，置信度低于逐句实录 |

##### Activity / 事：更像「行为、爱好、尝试、规则、懂不懂」

| 用法 | 可写成的占位符模板 | 实例 | 证据类型 | 说明 |
|------|------------------|------|----------|------|
| 问某人是否懂某项活动 | `[Mii] 很了解如何 [activity] 吗？` | `Frank 很了解如何喝点小酒吗？` | 逐句实录 [cite: 18] | 把 activity 当成一种技能/做法，而不是物品名。 |
| 研究某活动的规则 | `我/本人每天都会翻看 [activity] 的规则手册。` | `本人每天都会翻看喝点小酒的规则手册。` | 逐句实录 [cite: 18] | 与英文 `I study the [activity] rule book every night before bed!` 属同一 rule book 结构 [cite: 14]。 |
| 想尝试某活动 | `我一直想尝试一次规范的 [activity]！` | `我一直想尝试一次规范的喝点小酒！` | 逐句实录 [cite: 18] | activity 可被当作「以后想做一次」的愿望对象。 |
| 发现享受某活动的新方法 | `[Mii] 似乎知道享受 [activity] 的乐趣的新方法。` | `宫本茂似乎知道享受好好学习的乐趣的新方法。` | 逐句实录 [cite: 18] | activity 进入「享受/乐趣/方法」这一类轻闲聊模板。 |
| 机器人事件里被当成可懂词插入 | `机器人乱码 ... [activity/lingo] ... 机器人乱码` | Robot Rally 会在机器人胡言乱语中插入 Lingo、Food、Treasure 等可懂词 [cite: 4] | 事件描述 | 不保证专门抽 activity，但 activity 作为 Lingo 可进入这一类舞台事件。 |
| 旧聊天回顾 | `之前聊过 [activity/lingo]` | Catching Up 会回顾过去聊过的话题，包含 Lingo 与 Palette House 创作 [cite: 4] | 事件描述 | 对应「最近/之前只聊某话题」这一类回流句式。 |

**可读出的 activity 语法倾向**：常被放进「懂不懂」「研究规则」「尝试一次」「享受乐趣」「共同爱好」这些动词框架里。它不是被当作静态名词展示，而是被当作一件可以学习、实践、评价的事。

##### Person / 人：更像「像谁、崇拜谁、谁发来消息、谁代表某话题」

| 用法 | 可写成的占位符模板 | 实例 | 证据类型 | 说明 |
|------|------------------|------|----------|------|
| 外貌/气质相似 | `仔细一瞧，[Mii] 和 [person] 很像呢。` | `咦？仔细一瞧，小李和押沙龙很像呢。` | 逐句实录 [cite: 18] | person 可进入「某个 Mii 像某人」模板。 |
| 粉丝会主题 | `我是 [person] 的粉丝 / 我们来聊 [person]` | Fan Meetup 中，Person Lingo 会变成粉丝聚会主题 [cite: 4] | 事件描述 | 事件中央物件会换成粉色心形蛋糕，象征崇拜对象。 |
| 假邮件/远处目击 | `我收到自称是 [person] 的邮件`、`我在另一个岛上看到过 [person]` | Fan Meetup 会八卦 claiming to be the person 的邮件、在另一座岛上目击该人物等 [cite: 4] | 事件描述 | 这是目前公开资料里 person 类最具体的一组事件用法。 |
| 喜欢/感兴趣的类型 | `[Mii] 描述自己感兴趣的那类人： [person/lingo]` | Talking About Love 中，Mii 可能用 Lingo 描述一种人 [cite: 4] | 事件描述 | person 类不一定只指真实姓名，也可能被当成「理想类型/某类人」。 |
| 全岛复用名人 | `其他 Mii 在无关对话里又提起 [person]` | 输入 `John Cena` 后，其他 Mii 后续在不同对话里再次提起 [cite: 17] | 逐句/玩家记录 | 说明 person 不是绑定单个提问者，而是进全岛词库。 |
| 室友传闻：模仿某人 | `[Mii C] 在模仿 [person] 的举止，大家快分不清两者。` | Roommate Rumour 明确提到某 Mii copying all the mannerisms from a Person Lingo，并让旁人开始混淆两者 [cite: 4] | 事件描述 | 这是 person 类最直接的「像某人/学某人」事件证据。 |
| 群组代表性投票/询问 | `谁最能代表 [topic/person]？我们去问 [Mii]。` | Game8 的 Friendship Thought Bubbles 记录了 `Who in [Group Name] best represents a [Topic]? Let's ask [Mii].` [cite: 15] | 攻略转录 | 若 topic 填 person 类，会变成「谁最像/最代表这个人或类型」。 |

**可读出的 person 语法倾向**：person 类经常进入比较、崇拜、八卦、代表性、理想类型这几组社会关系模板。它的效果不是简单复读名字，而是把名字变成岛民之间评价彼此的标尺。

##### Thing / 物：更像「可展示、可比较、可被订购、可进入梦/新闻/cutscene」

公开资料对 thing 类逐句台词最少；但事件页能确认「Food / Treasure / Palette House creation / custom item」这类物件槽位在多个事件里反复出现。严格说，这些不一定全部等同于 Island Lingo 的 thing 类，但它们说明游戏里的「物」类回流常走物件/宝物/自定义创作管线。

| 用法 | 可写成的占位符模板 | 实例 | 证据类型 | 说明 |
|------|------------------|------|----------|------|
| 物件对决 | `[Mii A] 和 [Mii B] 拿出 [food/treasure] 对决，某人说自己输了/平手。` | Item Face-Off 会让两个 Mii 戏剧性拿出 Food 或 Treasure [cite: 4] | 事件描述 | 物类被当成「拿出来比」的实体。 |
| 爱情比喻 | `爱情就像 [food/treasure/lingo]。` | Talking About Love 会把爱情与 Treasure、Food 或 Lingo 作比较 [cite: 4] | 事件描述 | 抽象概念可被物类/词条拿来比喻。 |
| 机器人事件插词 | `机器人乱码 ... [thing/food/treasure] ...` | Robot Rally 会插入 Lingo、Food 或 Treasure 作为唯一可懂词 [cite: 4] | 事件描述 | 物类在舞台事件里常作为突兀笑点。 |
| 粉丝会中央物 | `大家围绕 [thing/treasure] 开粉丝会。` | Fan Meetup 若主题是 Treasure，会把该物放在桌子中央 [cite: 4] | 事件描述 | 物类不是只被提到，也会视觉化成事件中心。 |
| 订购/箱子话题 | `是谁订了几箱 [food/treasure]？` | House Meeting 的话题包括询问谁订了几箱 Treasure 或 Food [cite: 4] | 事件描述 | 物类进入同居/会议式生活琐事模板。 |
| 室友传闻：丢失家里的贵重物 | `[Mii C] 因为弄丢家里珍贵的 [object lingo] 而伤心。` | Roommate Rumour 明确提到某 Mii 因为尝试把家里的 prized Object Lingo 当冲浪板用而弄丢它 [cite: 4] | 事件描述 | 这是 Object Lingo 被当成「家中珍贵物」使用的强证据。 |
| 梦、新闻、cutscene 回流 | `[custom item] 出现在梦、新闻报道或其他 cutscene 中。` | Kotaku 观察到玩家自定义物件更容易进入梦、新闻和其他 cutscene [cite: 14] | 玩家媒体记录 | 这是 thing/自定义物件最强的长期回响证据之一。 |
| 边界样例：物名像人名一样参与关系句 | `[Mii] 邀请 [thing/name] 同住，[thing/name] 同意了。` | `巩俐邀请设备同住，设备就同意了。` | 逐句实录 [cite: 18] | 这里需保留疑问：若「设备」其实是 Mii 名，则不是 thing 类证据；若来自词条，则说明物名可被模板当成角色名使用。 |

**可读出的 thing 语法倾向**：物类最常被「实体化」：拿出来、摆桌上、订购成箱、作为梦/新闻道具、作为比喻对象。和 person/activity 相比，thing 类更依赖画面事件和道具系统，公开逐句转录较少。

##### Something else / 其他：更像「话题、抽象概念、近期执念、失败归因」

| 用法 | 可写成的占位符模板 | 实例 | 证据类型 | 说明 |
|------|------------------|------|----------|------|
| 交友失败归因 | `全怪 [other] 这个话题，没能和 [Mii] 成为朋友。` | `全怪 shameless 这个话题，没能和卡莎成为朋友。` | 逐句实录 [cite: 18] | other 可作为「聊天主题」进入成功/失败反馈。 |
| 近期只聊某话题 | `[Mii] 近期只会聊关于 [other] 的事情。` | `自己近期只会聊关于 shameless 的事情。就是这么一件事哦......` | 逐句实录 [cite: 18] | 对应 Lingo 的长期回流：一个抽象话题会变成角色近期执念。 |
| 抽象话题促成交友 | `[Mii A] 和 [Mii B] 围绕 [other] 成为朋友。` | Theodore Roosevelt 与 Samantha Parkington 围绕 `an election` 成为朋友 [cite: 13] | 玩家记录 | other/抽象概念可作为 bonding 话题。 |
| 抽象概念跨场景复用 | `[other] 在不相关 cutscene 中被其他 Mii 提起。` | `Democratic Socialism` 后续在相关 Mii 不在场的 cutscene 中也被讨论 [cite: 11] | 设计向玩家记录 | other 类最能体现「岛上流行话题」的幽默。 |
| 旧聊天回顾 | `我们之前聊过 [other/lingo]。` | Catching Up 会回顾过去聊过的 Lingo [cite: 4] | 事件描述 | 可解释「最近只聊某话题」的来源。 |
| 爱情/关系比喻 | `爱情像 [other/lingo]。` | Talking About Love 会把恋爱与 Lingo 比较 [cite: 4] | 事件描述 | other 类可以被拿来做荒诞比喻。 |
| 机器人事件插词 | `机器人乱码 ... [other/lingo] ...` | Robot Rally 可插入 Lingo 作为唯一听得懂的词 [cite: 4] | 事件描述 | 抽象词在机器人乱码中会形成突兀笑点。 |

**可读出的 other 语法倾向**：other 更像「话题标签」而不是人/物/活动；它经常进入「聊这个」「怪这个话题」「最近只聊这个」「拿这个比喻」这些句型。因此它特别适合装抽象概念、节目名、梗、社会议题、游戏名、奇怪短语。

#### 4.1 Activity（活动）

**已确认完整句型模板**：

> `I study the [activity] rule book every night before bed!`

- Kotaku [cite: 14] 转述玩家视频：Mii Walter White 说 *I study the cooking meth rule book every night before bed!*，并与 Jesse Pinkman 围绕 *cooking meth* 建立共同话题。
- 同结构变体：*In fact, I study the official Making People Smile Association Rule Book every night before bed.* [cite: 14]

**小剧场 / 事件场景**：

1. **交友 bonding 小剧场**：两 Mii 围绕同一 activity 找共同点（Walter / Jesse 例 [cite: 14]）。
2. **Tomoria — Robot Rally**：Miis 扮机器人，在机器人音效中穿插 Island Lingo [cite: 4]。

**归纳（置信度：Secondary + Tertiary）**：activity 类词条优先进入「研究某活动的 rule book / 围绕爱好聊天 / 尝试某活动」类句型与 bonding 场景。

---

#### 4.2 Person（人物）

**已确认用法**：

1. **Tomoria — Fan Meetup**：Miis 穿心形装扮，狂热表达对所录入**人物**的喜爱 [cite: 4]。
2. **跨场景提起**：输入 *John Cena* 后，**其他 Mii 在无关对话**中再次提起 [cite: 17]（另见 [[朋友收集梦想生活-Mii提问资料整理]]）。
3. **群组话题气泡**：*"Who in [Group Name] best represents a [Topic]? Let's ask [Mii]."* → Topic 槽可填 person 类 lingo [cite: 15]。

**小剧场场景**：崇拜某人、讨论名人、「谁最代表 X」类 cutscene。

---

#### 4.3 Thing（事物）

**已确认用法**：

1. **Fan Meetup** 也可 obsesses over **thing** 或 Palette House 自定义 treasure [cite: 4]。
2. **语法层**：thing 类可事后调整 **a / an**，说明会进入带冠词的物名词句型 [cite: 9, 10]。
3. **自定义物品回流**：Polygon [cite: 16] — 自定义食物/物品录入后会反复出现在各种情境（*lobsta cake* 例）。

**缺口**：公开资料中**缺少** thing 类在小剧场里的逐句台词转录；仅能确认 Fan Meetup、语法冠词与物品回流行为。

---

#### 4.4 Something else（其他 / 抽象）

**已确认用法**：

1. **交友 cutscene**：Mii 谈论 *an election* 时成为朋友，橙色词为玩家 lingo [cite: 13]。
2. **跨 cutscene 复用**：*Democratic Socialism* 在全岛反复出现，含相关 Mii 不在场的场景 [cite: 11]。
3. **分类定义**：something else = 放不进前三类的任意内容 [cite: 7]。

**小剧场场景**：选举、政治/社会概念等抽象话题作交友或闲聊核心词；不强制 fit 人名语法或 activity rule book 句型。

### 五、橙色交友气泡与小剧场的对应关系

Game8 [cite: 15] 列出的、会触发「指定 lingo → cutscene」的橙色气泡包括：

| Mii 台词（英文） | 玩家动作 |
|-----------------|---------|
| "I want to be friends with [Mii]." | 选择聊什么（新建或已有 lingo） [cite: 15] |
| "I think [Mii 1] and [Mii 2] would be fast friends." | 帮两人牵线并指定话题 |
| "I've been thinking lately that [Mii] and I could get to know each other better…" | 同上 |
| "I want to try living with [Mii]." | 同住 cutscene 需 topic match [cite: 5] |
| "Who in [Group Name] best represents a [Topic]?" | 选 lingo 作 Topic [cite: 15] |
| 表达感谢类（个人 / 群组） | 给 Mii 一句 gratitude 相关 lingo [cite: 15] |

上述场景中，玩家指定的 lingo **分类**决定系统从哪类模板池选句；当场 cutscene 文本中的 lingo 常以橙色显示 [cite: 13]。

#### 5.1 交友/引荐时，玩家输入的 lingo 后续怎样被用掉

这一类不是普通闲聊，而是 **橙色关系问题 → 玩家指定话题 → 关系 cutscene 消费该话题** 的流程。

| 触发语境 | 玩家输入/选择 | 当场用途 | 后续复用 |
|----------|---------------|----------|----------|
| Mii 想和另一个 Mii 交朋友 | 新建或选择一个 Island Lingo，并指定 person / thing / activity / something else 等类型 | 作为两人初次聊天的 bonding topic；成功时变成“因为聊这个而成为朋友”，失败时也可能变成失败归因 | 若进入 Island Dictionary，后续可被其他聊天、回忆、Tomoria 事件再次抽取 [cite: 5, 9, 13] |
| Mii 想把两个 Mii 介绍认识 | 同上 | 介绍者把该 lingo 当作两人破冰话题；等价于“让他们聊什么” | 同上；词条不只绑定这一次介绍，而会成为全岛词库的一部分 [cite: 5, 10] |
| Mii 想和另一个 Mii 同住 | 选择一个 lingo | 两个 Mii 需要说出/认同相同 lingo，才会推进同住 | 仍会留在 Island Dictionary 中继续被谈论 [cite: 5, 9] |
| House Meeting / 代表性询问 | 选择一个 lingo，常表现为 topic/adjective/person 类槽位 | 询问谁最能代表这个 topic；投票/选择会影响关系 | 可进入群体讨论、回忆与后续事件 [cite: 5, 15] |
| 表达感谢/感谢室友 | 选择一个 gratitude 语境的 lingo | 作为感谢话题或感谢理由进入 cutscene | 关系提升；词条本身仍可能被后续复用 [cite: 5, 15] |

可把它理解成两层消费：

1. **一次性剧情消费**：本次交友/引荐/同住 cutscene 立刻拿这个词当话题。比如玩家实录中的 `全怪 [other] 这个话题，没能和 [Mii] 成为朋友。`，以及 *an election* 作为交友话题让两人变成朋友 [cite: 13, 18]。
2. **词库长期消费**：词条进入 Island Dictionary 后，居民会继续谈论它；任天堂官方支持页还明确说，删除词条后居民会停止谈论该词条 [cite: 9]。这说明它不是只服务一次交友，而是加入全岛可抽取的文本池。

更细一点看，类型会影响后续模板的自然语义：

| 类型 | 交友/引荐里像什么 | 后续更容易进的模板 |
|------|------------------|--------------------|
| Person | “聊某个人/名人/角色/某类人” | Fan Meetup、像不像某人、谁最代表某人、八卦/模仿/崇拜 [cite: 4, 17, 18] |
| Activity | “聊一种活动/实践/玩法” | 规则手册、学习/尝试/享受、两人因为共同活动 bonding [cite: 14, 18] |
| Thing / Object | “聊某个东西/物件/宝物式对象” | 展示、比较、订购、房间/会议里的物件、物件被视觉化 [cite: 4, 9] |
| Something else | “聊一个抽象概念/话题/梗” | 成功/失败归因、爱情比喻、回忆过去、机器人乱码插词、人生建议 [cite: 4, 11, 13, 18] |

旧作 `Friend/Transcript` 页面反而能解释差异：旧作里 Mii 会问 `What should I talk about...`，玩家选的是固定选项，如 `Something funny`、`Gossip`、`Deep thoughts`、`Something serious`；介绍朋友时也是 `Small talk`、`Hobbies`、`Love`、`Money` 这类固定项 [cite: 19]。到了《Living the Dream》，Fandom `Problems` 页把这一步改写为“告诉他们使用什么 island lingo” [cite: 5]。所以你在新作里感到“很多是我输入的词”，是对的：新作把旧作固定话题按钮改造成了玩家自定义词库。

#### 5.2 为什么 Fandom Events 页里 Food / Treasure 特别多

Fandom `Events` 页不是专门写 Island Lingo 的页面，而是在整理所有事件。很多事件的槽位本来就不是玩家输入词，而是从 **Food、Treasure、Belonging、Clothes、Palette House creation、Island Lingo** 等不同池子抽东西 [cite: 4]。

所以页面里 Food / Treasure 多，主要有四个原因：

1. **Food / Treasure 是可枚举物品池**：wiki 编辑能稳定写成“这里会出现 Food 或 Treasure”；而 Island Lingo 是每个岛无限变化的玩家文本，难以逐句列举。
2. **Events 页偏物件事件**：比如云、星座、对决道具、巨大跟随物、烟花形状、食物制作等，本来就是视觉化物件槽位，因此自然常写 Food / Treasure [cite: 4]。
3. **旧作和新作混在同页**：旧作 Tomodachi Quest 等事件天然大量使用 Food/Treasure 作敌人或奖励；这些会让整页看起来更像“食物/宝物游戏” [cite: 4]。
4. **玩家自定义词常被写成 Lingo，而不是展开成具体内容**：wiki 只能写“使用 Lingo”，无法知道你的岛上填的是 `shameless`、`喝点小酒`、`an election` 还是某个人名。你的体感来自实际存档里的 Island Dictionary，wiki 体感来自可统一记录的系统槽位。

因此，Fandom 的 Food/Treasure 和你游戏里的“我输入的词”不矛盾：它们是两套并列槽位。**Food/Treasure 是系统物品池；Island Lingo 是玩家文本池。** 有些事件只抽物品池，有些事件抽 Lingo 池，还有些事件会混用两者。

#### 5.3 Fandom Wiki 站内新增证据：Lingo 输入后的完整消费链

Fandom 站内其实已经有一个专门的 `Lingo` 页面。该页把 Lingo 定义为《Living the Dream》独有功能：允许 Mii 说出玩家创建的词语或短语；它与升级礼物给 Mii 的个人短语分开，因为 Lingo 可以被任何 Mii 在任意时间使用，包括对话和事件中，互动里常以橙色高亮显示 [cite: 20]。

按 Fandom 目前能确认的内容，玩家输入后的消费链可以整理为：

| 输入入口 | 输入后保存/限制 | 之后怎么用 | Fandom 证据 |
|----------|----------------|------------|-------------|
| 普通提问 / speech bubble 问答 | 部分问题允许玩家输入，加入岛屿 lingo dictionary | 进入后续玩家对话、Mii 对话与事件池 | `Lingo` 页与 `Problems` 页都写到 question/chat 可把玩家输入加入词典 [cite: 5, 20] |
| 交友 / 引荐两个 Mii | 玩家可选择创建 Lingo，并在 `person / thing / activity / something else` 中选类型 | 作为当场破冰话题；成功/失败反馈会直接提到该 Lingo | `Lingo` 页说明不同类型会导致不同事件和对话；台词页有成功/失败占位符 [cite: 20, 21] |
| Chat problem 的指定语境输入 | Mii 要玩家告诉它某种具体内容，如“不酷的短语” | 被放入词典，并在特定上下文复用，如坏心情打招呼、打架逃跑等 | `Lingo` 页与 `Problems` 页都明确写“specific contexts” [cite: 5, 20] |
| 想同住 | 只能输入 activity | 保存为 Lingo；随后两人讨论该活动，若两人同时说中同一个活动则同住成功 | `Lingo` 页和 `Shared House` 页均确认 [cite: 20, 24] |
| 室友感谢 | 只能输入句子 / phrase | 每个室友在感谢 cutscene 中说出这句话，并提升关系 | `Lingo` 页和 `Shared House` 页均确认 [cite: 20, 24] |
| House Meeting 投票 | 玩家输入 adjective 型 Lingo | 全家投票“谁最符合这个形容词”；若结果不是发起者且非平票，提升关系 | `Lingo`、`Problems`、`Shared House` 三页都能互证 [cite: 5, 20, 24] |
| 升级礼物行为 | 不是直接输入入口，而是已保存 Lingo 的消费场景 | 吉他歌词、空手道/玩具剑动作、笔记本邮件或招募信息中会使用 Lingo | `Level-Up Gifts` 页与台词页都有对应描述/台词 [cite: 21, 25] |
| 梦境 / 婚礼 / 独处想法 | 不是输入入口，而是长期消费场景 | RPG、Food Group Chat、Streetlamp 梦、婚礼歌曲、独处台词等会插入 Lingo | `Lingo` 页汇总了这些消费场景 [cite: 20] |
| Mii News milestone | 不是具体台词消费，而是数量统计奖励 | 10/20/50/100 个 Lingo 时触发新闻，证明系统把它当作可累计的全岛词库 | Mii News 列表有 10、20、50、100 四档新闻 [cite: 23] |

Fandom 的 `Mii/Speech Bubble Dialogue` 页比 `Events` 页更像“台词库”。该页按用途收录了大量 `[Island Lingo]` 占位符，可以反推不同类型被怎样塞进句子里：

| Lingo 类型/槽位 | Fandom 台词模板例 | 说明 |
|-----------------|------------------|------|
| Activity-based | `I practise [Island Lingo] for a couple of hours every day.` / `Recently, [Island Lingo] with friends has become the absolute highlight of my week.` | 活动类常接“练习、尝试、掌握、和朋友一起做”等动词 [cite: 21] |
| Person-based | `I really admire [Island Lingo]'s whole way of life.` / `You remind me of [Island Lingo].` | 人物类常进入崇拜、像不像、上电视、周边、粉丝语境 [cite: 21] |
| Object-based | `I always get jealous when I see someone with a/an [Island Lingo].` / `Which is worth more: a/an [Custom Treasure] or a/an [Island Lingo]?` | 物件类会用 `a/an`，并和 treasure、item、持有/买卖/气味等语境混用 [cite: 21] |
| Phrase-based | `There's an old saying... "[Island Lingo]".` / `When is the right time to say "[Phrase-based Island Lingo]"?` | 句子/短语类会被当成引号内原句、格言、邮件话题、感谢台词 [cite: 21] |
| Adjective-based | `I was nominated for the [adjective-based Island Lingo] award.` / `Do you think [Mii] is a bit of a/an [adjective-based Island Lingo]?` | 形容词类被当作人设标签、奖项、评价别人、House Meeting 投票依据 [cite: 21] |
| Any Island Lingo | `I could talk about [Island Lingo] all day.` / `I was up all night thinking about [Island Lingo].` | 泛用槽位不强制分类，重点是“热门话题/执念/最近老在聊” [cite: 21] |

关系结果台词也能进一步确认“交友输入词”的当场用法：

| 场景 | Fandom 占位符模板 | 结论 |
|------|------------------|------|
| 直接交友成功 | `When I talked to [Mii] about [Island Lingo], we both got super into it. Now we've ended up friends!` | 输入词作为两人聊到投缘的具体话题 [cite: 21] |
| 直接交友成功 | `I talked to [Mii] and I learned that ... they're into [Island Lingo].` | 成功逻辑可解释为发现对方也喜欢该话题 [cite: 21] |
| 引荐成功 | `I'm mates with [Mii] after [Mii] introduced us! [Mii] likes [Island Lingo] and everything!` | 引荐人牵线后，Lingo 仍是被介绍双方的共同话题 [cite: 21] |
| 三方引荐成功 | `I got [Mii] to meet [other friend Mii]... both of them like talking about [Island Lingo] so much...` | 系统会把共同喜欢聊某词作为友情成立理由 [cite: 21] |
| 交友失败 | `I tried chatting with [Mii] about [Island Lingo]... But it was like we were having two different conversations.` | 失败不是词条消失，而是这次关系 cutscene 判定没接上 [cite: 21] |
| 同住成功 | `Seems like [Mii] wants to share a home where we can spend time [Island Lingo] together!` | 同住请求把 activity Lingo 转成“以后一起做的活动” [cite: 21] |
| 感谢室友 | `... really likes saying "[phrase-based Island Lingo]"!` | 感谢类输入被当成室友之间说出口的短句 [cite: 21] |

除关系 cutscene 外，Fandom 还能确认这些长期消费场景：

| 消费场景 | 具体用法 | Fandom 证据 |
|----------|----------|-------------|
| 玩家与 Mii 日常对话 | Mii 会在问候、点气泡、谈朋友时使用词典里的 Lingo | `Lingo` 页的 Interacting with Miis [cite: 20] |
| 岛上旁观 Mii 交谈 | 旁观文本会提到 treasure、lingo 或二者混合；`Conversation` 页也说新作旁观对话会插入 treasure、food、lingo、岛民名字 | `Lingo` 与 `Conversation` 页 [cite: 20, 26] |
| Tomoria / building cutscene | Robot Rally、Fan Meetup、Awkward Conversation 等会使用玩家 Lingo | `Cutscene` 页明确写 Robot Rally、Fan Meetup、Awkward Conversation [cite: 22] |
| Fight / 吵架 | 活动类可被骂无聊；人物类可被争论是否伟大；形容词类可用于“我比你更像某某”；活动类可用于“我比你更擅长” | Fight transcript 页面源码中有多条 Lingo 占位符 [cite: 27] |
| Level-up gifts | 吉他歌词、Jogging DVD、笔记本邮件/博客、玩具剑等会插入 phrase/person/activity Lingo | 台词页和 Level-Up Gifts 页互证 [cite: 21, 25] |
| 梦境 | RPG、Food Group Chat、Streetlamp 梦会使用 Lingo | `Lingo` 页汇总 [cite: 20] |
| 婚礼 | 婚礼歌手可能用随机 Lingo 描述新婚二人 | `Lingo` 页 Weddings 小节 [cite: 20] |
| Mii News | 10/20/50/100 个 Lingo 触发新闻与 speech bubble 奖励 | Mii News 列表 [cite: 23] |

这次 Fandom 补查后，可以把机制进一步压缩成一句：**Island Lingo 是“全岛共享、按类型标注、不可改正文但可改发音/冠词的文本词库”；输入后会先被当前问题消费，再作为全岛词库，被日常对话、关系反馈、旁观 caption、Tomoria、Shared House、升级礼物、梦、婚礼、新闻统计等系统持续抽取。** [cite: 20, 21, 23, 24]

#### 7.5 从 Events 全表反推 Island Lingo 的用法

| 事件族 | 可复用槽位 | 对 Island Lingo 设计的启发 |
|--------|------------|----------------------------|
| 直接 Lingo 事件 | Catching Up、Talking About Love、Robot Rally、Fan Meetup、Roommate Rumour、Heavenly Advice | Lingo 不只进入聊天句子，也能进入“回忆过去”“爱情比喻”“机器人乱码插词”“粉丝会”“室友传闻”“人生建议”。 |
| Food / Treasure 物件事件 | Check out the Sky、Item Face-Off、Follower、House Meeting、Co-op Cooking、Ants Ahoy、Migration Observation、Grand Finale 等 | 物件类内容常被视觉化：云、星座、对决道具、巨大追踪物、订购物、食物、烟花形状。 |
| Palette House / 自定义创作事件 | Catching Up、Creation Admiration、Fan Meetup 等 | 玩家自定义创作可进入被欣赏、被回忆、被围观的事件。 |
| 关系状态事件 | Talking About Love、Let My Thoughts Reach You、A Sly Wink、Love at First Sight、Daydreaming、Practice Run | 小剧场常用同一套槽位表现关系：暗恋、告白练习、恋爱比喻、幻想未来。 |
| 场所/物件触发事件 | See-Saw、Bubble Blowers、Toy Swords、Clock、Bell、Pinwheel、Firework、Trash Can 等 | 可把岛上摆放物设计成事件触发器，而不是只当装饰。 |

因此，如果要把 Island Lingo 系统迁移到其他生活模拟游戏，不能只做“角色偶尔复读玩家词条”。更接近《Living the Dream》的做法是：把玩家输入内容拆成 person / object / activity / other 等槽位，再分别接入关系事件、物件事件、舞台事件、闲聊事件和家庭传闻事件。

### 九、结论

1. **分类不是装饰**：person / thing / activity / something else 影响词条进入哪套对话模板、Tomoria 事件与语法（a/an），并决定 Fan Meetup、Robot Rally 等场景的匹配方式。
2. **小剧场 = 多类 scene 的总称**：拖动互动 [cite: 1]、hangout [cite: 2]、橙色交友 cutscene [cite: 3]、Tomoria 表演 [cite: 4] 均可能插入 Island Lingo；机制上是 **storylet 选模板 + 从 Dictionary 按类抽词填槽 + 全岛随机轮播** [cite: 10, 11]。
3. **目前唯一能写全句的活动类模板**：`I study the [activity] rule book every night before bed!` [cite: 14]。
4. **person / 抽象类**有 Fan Meetup [cite: 4]、John Cena [cite: 17]、*an election* [cite: 13]、*Democratic Socialism* [cite: 11] 等可校验样例。
5. **thing 类**有 Fan Meetup [cite: 4]、a/an 语法 [cite: 9, 10] 与物品回流 [cite: 16]，但**缺逐句小剧场转录**。
6. 新增中文实录后，可以更具体地看出四类句法差异：activity 偏「懂/学/试/享受」，person 偏「像/崇拜/代表/八卦」，thing 偏「展示/比较/订购/进入事件画面」，other 偏「话题/执念/失败归因/抽象比喻」[cite: 18]。
7. 设计借鉴时：应把 lingo 当 **分类槽位词库**，而非「保存字符串后原样复读」；并预留 Chat 类 lingo 的**语境绑定** [cite: 5]（如过时潮流 → 易怒打招呼）。
